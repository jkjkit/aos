# LLM Evaluation

把“模型感觉不错”转化为可重复、可比较、能阻止能力退化的评估证据。

## 何时使用

- 需要比较模型、Prompt、检索策略或 Agent 版本
- 为 LLM 功能建立离线评估集、评分标准和发布门禁
- 分析幻觉、指令遵循、工具调用、引用质量或安全性失败
- 需要校准人工评审、规则评估器或 LLM-as-a-judge

不要用于：

- 编写或优化 Prompt 正文（用 `prompt-writing`）
- 设计生产流量上的随机对照实验（用 `ab-testing`）
- 测试普通确定性代码功能（用 `testing`）
- 只运行现有构建、lint 和测试门禁（用 `verification`）
- 设计上下文选择、压缩和记忆策略（用 `context-engineering`）

## 评估契约

开始前明确：

- **被评对象**：模型、Prompt、RAG、Agent 或完整链路
- **任务单位**：一次输入输出、一次对话、一次工具执行或一个完整任务
- **成功定义**：哪些质量维度决定可接受
- **对照基线**：当前生产版本、人工答案或固定参考实现
- **决策规则**：什么结果允许发布，什么结果必须阻断

## 流程

1. **定义任务与风险**：列出核心能力、关键失败模式、用户影响和不能退化的护栏
2. **构建评估集**：覆盖典型、边界、对抗、历史故障和长尾样本；记录来源、许可、版本与泄漏风险
3. **设计评分标准**：把“好”拆成可判定的维度、等级和锚点示例，区分硬失败与偏好差异
4. **组合评估器**：优先确定性检查，其次人工评审，再使用经过校准的模型评审；不要让单一评估器决定全部结论
5. **校准与盲测**：使用人工金标检查一致性、偏差和顺序效应；评审时隐藏候选身份
6. **运行基线与候选**：固定模型参数、工具版本、检索语料和随机性设置，记录失败与重试
7. **分析结果**：报告总体指标、分层结果、置信区间、失败簇和相对基线变化，不只给平均分
8. **设置回归门禁**：为关键维度设置最低值、允许退化幅度和必须人工复核的条件
9. **保存可复现资产**：版本化评估集、Rubric、评估器配置、运行环境和结果摘要

完成标准：每个发布决策维度都有代表性样本、明确评分规则、可信评估器、基线对比和可执行门禁。

## 评估器选择

| 评估器 | 适合 | 主要风险 |
|---|---|---|
| 确定性规则 | 格式、JSON、引用、工具参数、关键词约束 | 无法判断语义质量 |
| 参考答案指标 | 分类、抽取、标准问答 | 多个正确答案时误判 |
| 人工评审 | 高风险、主观质量、金标校准 | 成本、一致性与疲劳 |
| 模型评审 | 大规模语义评分、成对比较 | 自偏好、位置偏差、理由幻觉 |
| 端到端任务结果 | Agent 是否真正完成任务 | 环境噪声和归因困难 |

## 输出格式

```markdown
# LLM Evaluation Report

## 评估契约
- 被评对象：...
- 基线：...
- 发布门禁：...

## 数据集
| 分层 | 样本数 | 来源 | 主要风险 |
|---|---:|---|---|

## 指标与评估器
| 维度 | 评估器 | 评分标准 | 门禁 |
|---|---|---|---|

## 结果
| 维度 | 基线 | 候选 | 变化 | 置信度 | 状态 |
|---|---:|---:|---:|---|---|

## 失败模式
- [失败簇、代表样本、影响和建议]

## 结论
**Pass / Fail / Inconclusive**
```

## 行为准则

- **评估先于调参**：先固定衡量方式，再优化模型或 Prompt
- **分层胜过均值**：关键用户和高风险任务不能被总体平均掩盖
- **校准模型评审**：未经人工金标验证的 Judge 结果只能作为辅助证据
- **防止数据污染**：训练、开发和最终评估样本保持隔离
- **报告不确定性**：样本不足或评估器不一致时给出 `Inconclusive`
