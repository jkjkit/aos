# Security

对一段代码、接口、配置或依赖做安全审查，产出按严重程度排序的发现与修复建议。

## 何时使用

- 新功能涉及认证 / 授权 / 敏感数据
- 上线前安全审查
- 收到漏洞报告需要评估
- 接入第三方依赖或服务
- 定期安全巡检

不要用于：

- 仅排查运行错误（用 debug）
- 仅性能问题（用 performance）
- 个人信息分类、目的、最小化、同意、保留、删除和第三方共享审查（用 `privacy-review`）
- 业务功能未稳定（先 coding）

## 流程

1. **明确边界**：识别系统边界与信任域；梳理数据流（输入 → 处理 → 存储 → 输出）
2. **威胁建模**：用 STRIDE 类别（欺骗 / 篡改 / 抵赖 / 信息泄露 / 拒绝服务 / 权限提升）；重点场景单列
3. **逐项审查**：
   - 认证与会话
   - 授权与访问控制
   - 输入校验与注入
   - 输出编码与敏感数据暴露
   - 加密与密钥管理
   - 依赖与配置
4. **汇总发现**：按严重程度排序；给出复现条件、影响范围、修复建议
5. **输出报告**

## 输出格式

```markdown
# Security Audit Report

## 范围
- 对象：[模块 / 接口 / 配置]
- 时间：[审查时间]

## Findings

### S-001: 标题
- Severity: Critical / High / Medium / Low
- Category: Auth / Input / Output / Crypto / Dependency / Config
- Location: [文件 / 接口]
- Description: [问题描述]
- Impact: [影响]
- Recommendation: [修复建议]
- Reproducible: [如何复现或验证]

### S-002: ...

## 按严重程度统计
- Critical: N
- High: N
- Medium: N
- Low: N

## 遗留风险与监控建议
- ...
```

## 严重程度

- **Critical**：立即可被远程利用、影响大量数据
- **High**：有明显利用路径，但需要特定条件
- **Medium**：条件复杂或影响有限
- **Low**：信息泄露、风格类问题

## 必查清单

- 密码哈希（bcrypt / Argon2，不要 MD5 / SHA1）
- Token 过期与撤销机制
- SQL 注入（参数化查询）
- XSS（输出编码 + CSP）
- CSRF（Token + SameSite）
- CORS 配置
- 速率限制
- 敏感数据日志（密码、Token 不应进日志）
- 依赖漏洞扫描（npm audit / Snyk）
- 环境变量管理（密钥不入库）
- HTTP 安全头（HSTS、CSP、X-Frame-Options）
- 文件上传校验（类型、大小、存储位置）

## 行为准则

- **不臆测攻击路径**：没把握就标「未验证」，不要编
- **不暴露完整 Payload**：报告里只描述类型，不给可粘贴的攻击字符串
- **给可执行的修复**：方向要明确，不要写「加强校验」这种空话
- **承认不在范围内**：DDoS、0day、社会工程不在此 Skill 范围

## 不要做的事

- 不要直接动生产环境
- 不要把 SAST / SCA 工具的告警原样照抄——做去重和优先级判断
- 不要忽略配置类问题（多数事故根因在配置而非代码）
- 不要把「安全建议」当成「必须立即修」——分级很重要
