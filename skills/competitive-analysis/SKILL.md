# Competitive Analysis

系统性分析与竞品的差异——功能、定位、用户、技术。**不**做用户研究（用 `user-research`），**不**写产品需求（用 `requirement`），**不**做技术调研（用 `research`）。

## 何时使用

- 进入新市场前
- 新功能规划（看竞品怎么做的）
- 战略调整（找差异化机会）
- 投资人 / 高管汇报

不要用于：

- 写需求规格 → `requirement`
- 用户研究 → `user-research`
- 技术调研 → `research`
- 设计参考 → `design-interface`

## 流程

### 1. 明确目标

- **为什么做这次分析**？（决策：进入市场 / 调整策略 / 找差异化）
- **决策依据是什么**？（输出形式：报告 / 矩阵 / 战略建议）
- **时间预算**？（竞品分析是个无底洞）

### 2. 识别竞品

按层级：

| 层级 | 说明 | 例子 |
|------|------|------|
| **直接竞品** | 解决同一问题的同类产品 | Slack vs Discord |
| **间接竞品** | 不同方式解决同一问题 | Notion vs Word + Google Docs |
| **参考竞品** | 跨行业值得借鉴的产品 | Linear（项目协作借鉴 Notion 设计） |
| **替代方案** | 用户「不做什么」的替代 | 用户不用工具，用手记账 |

**数量控制：3-5 个**。太多难以分析，太少信息不足。

### 3. 选择对比维度

#### 通用维度

| 维度 | 子项 |
|------|------|
| **产品定位** | 目标用户 / 核心价值主张 / 价位 |
| **功能** | 核心功能 / 差异化功能 / 缺失功能 |
| **体验** | UI / 性能 / 学习曲线 / 文档 |
| **技术** | 平台 / 架构 / 开放性 / 性能 |
| **商业** | 定价 / 商业模式 / 客户群 / 营收 |
| **市场** | 用户量 / 增长 / 留存 / 口碑 |

#### 按场景选

- 做战略决策 → 偏「产品定位」「商业」「市场」
- 做功能规划 → 偏「功能」「体验」
- 做技术选型 → 偏「技术」

### 4. 数据收集

**信息来源（按可信度排序）：**

1. **官方资料**：官网、定价页、文档、Changelog
2. **一手体验**：注册试用、跑核心流程
3. **用户评价**：G2 / Capterra / 知乎 / Reddit / X
4. **行业报告**：Gartner / Forrester
5. **逆向分析**：抓包、看 JS、看 API
6. **第三方数据**：SimilarWeb / Sensor Tower

**避免：**

- ❌ 只看营销文案（每个产品都说自己最好）
- ❌ 听一面之词
- ❌ 用 1 个用户的吐槽当结论

### 5. 矩阵分析

#### 功能矩阵

```
功能       A   B   C   我们
─────────────────────────
核心功能1   ✓   ✓   ✓    ✓
核心功能2   ✓   ✓   ✗    ✓
差异功能A   ✓   ✗   ✗    ✗  ← 我们的缺口
差异功能B   ✗   ✓   ✗    ✗  ← 我们的机会
```

#### 定位矩阵

```
        高价 ←────→ 低价
高端用户 │   [A]    │        │
         │          │        │
─────────────────────────
大众用户 │   [C]    │ [我们] │ [B]
         │          │        │
        ← 功能多 ──── 功能少 →
```

### 6. 差异化策略

**找到差异化的 3 个角度：**

| 角度 | 含义 |
|------|------|
| **目标用户不同** | 服务被忽视的细分人群 |
| **解决问题不同** | 用新方法解决同一痛点 |
| **体验不同** | 同方法 + 显著更好体验 |

**避免：**

- ❌ 「我们也做」 → 没有差异化，红海
- ❌ 「我们更快」 → 不可持续，会被赶上
- ❌ 「我们更便宜」 → 价格战陷阱

## 输出格式

```markdown

- 决策：[要做什么决定]
- 时间：[这次分析的时间窗口]

## 竞品
- [直接竞品 A / B]
- [间接竞品 C]
- [参考 D]

[按场景选 5-8 个维度]

## 矩阵
[功能矩阵 / 定位矩阵]

- [行动 2]
```

## Hard Rules

### 禁止：只选一个竞品对比

```
❌ 「我们和 A 比有 5 个优势」
✅ 至少 3-5 个竞品矩阵对比
```

### 禁止：用营销材料当事实

```
❌ 「A 说自己是行业第一，所以是行业第一」
✅ 注册试用、查第三方数据、看用户评价
```

### 禁止：差异化只是「更快更便宜」

```
❌ 「我们比 A 快 30%」（不可持续）
✅ 「我们专注 X 用户群的 Y 场景」（可持续）
```

### 禁止：分析变产品功能清单

```
❌ 「竞品有 X，我们也要有」
✅ 「竞品有 X 解决 Y 问题，我们要解决 Y 还是 Z？」
```

## 行为准则

- **多源验证**：至少 2 个独立来源
- **体验优先**：自己跑一遍比读 100 篇评测强
- **动态视角**：竞品在变，定期更新（建议季度）
- **客户视角**：用户为什么选 A 而不是我们？
- **承认未知**：数据不足时明说，不瞎补

## 与其它 Skill 的协作

| Skill | 关系 |
|---|---|
| `requirement` | 下游：分析 → 需求 |
| `design` | 下游：分析 → 设计差异化 |
| `research` | 并行：技术调研可并行 |
| `user-research` | 并行：用户视角补充 |
| `roadmap` | 下游：差异化 → 路线图 |
