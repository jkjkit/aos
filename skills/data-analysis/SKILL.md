# Data Analysis

通用数据分析方法论。**不**写 SQL（用 `database`），**不**设计指标体系（用 `metrics-design`），**不**做 A/B 测试（用 `ab-testing`）。

## 何时使用

- 已有数据，要提炼洞察
- 制作数据报告 / 看板
- 回答业务问题：「为什么指标变了」
- 探索性数据分析（EDA）

不要用于：

- 设计指标 → `metrics-design`
- A/B 测试 → `ab-testing`
- 同期群分析 → `cohort-analysis`
- 写 SQL 取数 → `database`

## 四类分析

```
描述性 (Descriptive)    发生了什么？     —— 报告、看板
诊断性 (Diagnostic)      为什么发生？     —— 归因分析
预测性 (Predictive)      会发生什么？     —— 预测模型
处方性 (Prescriptive)    应该怎么做？     —— 决策建议
```

大多数业务分析是**描述性 + 诊断性**。预测和处方需要数据科学 / ML 背景。

## 流程

### 1. 明确问题

在动手前先回答：

- **业务问题是什么**？（不是数据问题）
- **决策是什么**？（这个分析用来支持什么决定）
- **受众是谁**？（高管 / 业务 / 工程）
- **时间窗口**？（日 / 周 / 月 / 季度）

**好问题示例：**

- 「过去 3 个月用户活跃度为什么下降？」
- 「新功能上线后对核心指标有什么影响？」
- 「下个季度我们应该重点投入哪个用户群？」

### 2. 收集数据

数据来源：

| 类型 | 来源 |
|------|------|
| 业务数据 | 数据库（用 `database` 取数） |
| 行为数据 | 埋点 / 分析平台 |
| 调研数据 | 问卷 / 访谈（用 `user-research`） |
| 外部数据 | 行业报告 / 公开数据 |

### 3. 数据清洗

常见问题：

- **缺失值**：删除 / 填充 / 标记
- **重复值**：去重
- **异常值**：识别 + 判断是噪声还是真实信号
- **不一致**：单位、命名、时间戳
- **样本偏差**：覆盖是否完整

### 4. 分析方法

#### 描述性分析

- **汇总统计**：均值 / 中位数 / 分位数 / 标准差
- **分布**：直方图、密度图
- **趋势**：时间序列、滚动平均、环比 / 同比
- **对比**：分组对比、A vs B

#### 诊断性分析

- **归因**：指标变化由谁造成（拆解 / 占比）
- **相关性**：相关系数（注意：相关 ≠ 因果）
- **分布差异**：不同群体的分布对比
- **路径分析**：用户从 A 到 B 的路径

#### 注意事项

- 相关性 ≠ 因果性（冰激凌销量和溺水率都涨，但都因为夏天）
- 小样本可能误导（100 个用户不能下结论）
- 注意辛普森悖论（分组与整体的结论相反）

### 5. 可视化

**选对图：**

| 目的 | 推荐图 |
|------|--------|
| 趋势 | 折线图 |
| 对比 | 柱状图 |
| 占比 | 饼图 / 堆叠柱状图（少用饼图） |
| 分布 | 直方图 / 箱线图 |
| 相关性 | 散点图 |
| 地理 | 地图 |

**常见错误：**

- ❌ 3D 饼图（扭曲比例）
- ❌ 双 Y 轴折线图（误导）
- ❌ 太多颜色 / 太多线条
- ❌ 截断 Y 轴（夸大差异）

### 6. 报告结构

```markdown
# 数据分析: <主题>

## 摘要（Executive Summary）
- 核心发现：1-2 句话
- 建议行动：1-3 条
- 决策点：需要决策者回答的问题

## 背景
- 业务问题
- 时间窗口
- 数据来源

## 关键发现

### 发现 1: [标题]
- 数据：
- 解读：
- 业务意义：

### 发现 2: ...

## 建议行动
- [行动 1]
- [行动 2]

## 局限与风险
- 数据局限：
- 结论局限：
- 需要进一步分析：
```

## 输出格式

```markdown
# Analysis: <问题>

## 业务问题
[一句话]

## 方法
- 数据：[来源 / 时间窗口 / 样本量]
- 分析方法：[描述 / 诊断 / 预测]

## 关键发现

### Finding 1: ...
### Finding 2: ...

## 可视化
[图表说明 / 推荐图]

## 建议
- [行动 1]
- [行动 2]

## 风险
[结论局限]
```

## Hard Rules

### 禁止：用相关性证明因果

```
❌ 「A 和 B 相关，所以 A 导致 B」
✅ 「A 和 B 相关，可能的原因有 X、Y、Z，需要进一步验证」
```

### 禁止：忽略样本量

```
❌ 「100 个用户的结果可以代表所有人」
✅ 「样本量 100，结论仅适用于类似场景，需要更大样本验证」
```

### 禁止：选择性展示

```
❌ 只展示支持自己观点的图表
✅ 全面展示，并解释为什么排除其他可能
```

### 禁止：报告里不下结论

```
❌ 「数据显示有变化」（那又怎样？）
✅ 「数据显示 X 变化，建议 Y 行动」
```

## 行为准则

- **业务问题先行**：先问「为什么做这个分析」
- **方法透明**：让读者能复现
- **结论谨慎**：区分观察 / 推断 / 结论
- **建议可执行**：每个建议都有 owner + 时间
- **承认不确定**：置信度低的结论要标出

## 与其它 Skill 的协作

| Skill | 关系 |
|---|---|
| `metrics-design` | 上游：先有指标才能分析 |
| `cohort-analysis` | 上下游：同期群分析是常用方法 |
| `ab-testing` | 上下游：A/B 测试结果需要分析 |
| `database` | 并行：取数依赖 SQL |
| `summary` | 上下游：分析结果可被提炼 |
