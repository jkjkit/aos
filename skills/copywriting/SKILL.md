# Copywriting

把产品 / 想法 / 数据 → 打动目标受众的文字。**不写代码，不写技术文档**（那是 `document`），**不写需求规格**（那是 `requirement`）。

## 何时使用

- 写营销文案（产品介绍、落地页、宣传语）
- 写社交媒体帖子（微博、Twitter、LinkedIn、公众号）
- 写邮件（冷邮件、Newsletter、产品公告）
- 写广告创意（Google Ads、Facebook Ads、信息流）
- 写品牌叙事（About Us、用户故事、创始故事）
- 写短视频脚本（抖音、Reels、YouTube Shorts）

不要用于：

- 写代码、API 文档（用 `coding` / `api-design`）
- 写技术文档、README（用 `document`）
- 写需求规格（用 `requirement`）
- 写会议纪要（用 `meeting-notes`）

---

## 核心原则

借鉴自 taste-skill 的 Anti-Slop 哲学与一线营销经验：

- **受众先于文案**：写给谁看，决定一切
- **具体胜过抽象**：给数字、给场景、给名字
- **一个核心信息**：不要堆功能列表
- **真实胜过夸张**：用客户故事而非「极致体验」
- **翻译优先于直接写**：用户说「高级感」先翻译成具体表达

## 流程

### 1. 锚定受众

在写第一行字之前回答：

- 受众是谁？（角色、年龄、行业）
- 他们在什么场景下读这个文案？
- 他们已经知道什么？（避免重复）
- 他们最关心什么？（不是「我们能做什么」，是「他们能得到什么」）

### 2. 翻译模糊描述

用户给的形容词都是「感觉层」描述，要翻译成「具体层」：

| 用户说的 | 翻译成 |
|---|---|
| 高级感 | 克制用词 + 具体数字 + 真实案例 + 不堆形容词 |
| 年轻化 | 短句 + 第二人称 + 行动号召 + 反套路 |
| 专业感 | 行业术语 + 数据 + 引用权威来源 + 避免口语 |
| 紧迫感 | 截止日期 + 限量 + 损失厌恶 + 具体后果 |
| 温暖感 | 第二人称 + 真实故事 + 共情场景 + 弱化推销 |

### 3. 选结构

不同场景用不同结构：

| 场景 | 结构 |
|---|---|
| 落地页 | 标题 → 共鸣问题 → 解决方案 → 信任背书 → 行动号召 |
| 冷邮件 | 钩子 → 共情 → 价值主张 → 具体案例 → 低门槛 CTA |
| 社交媒体 | 钩子句 → 价值点 → 互动问题 → 标签 |
| 品牌故事 | 起源 → 转折 → 信念 → 行动 |
| 广告创意 | 标题 → 痛点 → 解决方案 → 紧迫感 → CTA |

### 4. 写第一稿

**先写最差的版本**——避免陷入完美主义。

然后按 Anti-Slop Hard Rules 改写。

### 5. Anti-Slop 自查

- [ ] 没有「极致」「赋能」「重磅」「全新升级」等空话
- [ ] 没有堆砌形容词（强大 + 专业 + 高效 + 智能 + ...）
- [ ] 至少有一个具体数字 / 案例 / 名字
- [ ] 核心信息一句话能讲清
- [ ] CTA（行动号召）明确且单一
- [ ] 没有「我们有 X 也有 Y 也有 Z」的功能堆叠

### 6. 输出格式

```markdown
# Copy: <场景>

## 受众
[角色 / 场景 / 关注点]

## 核心信息
[一句话：这条文案要让读者记住什么]

## 风格锚点
[品牌调性 / 参考样本 / 情绪]

## 文案

### 版本 1：[结构名]
[正文]

### 版本 2：[结构名]
[正文]

## 验证清单
- [ ] 一句话能讲清核心信息
- [ ] 有具体数字 / 案例
- [ ] 没有营销腔
- [ ] CTA 明确
- [ ] 受众读得懂
```

## Hard Rules（绝对禁止）

### 禁止：营销腔

```
❌ 极致体验、赋能业务、重磅发布、全新升级、匠心打造
✅ 我们把这个流程从 3 天缩短到 30 分钟
```

### 禁止：堆形容词

```
❌ 强大、专业、高效、智能、稳定、安全、可靠
✅ 99.99% 可用性 / 30 秒部署 / 100 万日活
```

### 禁止：功能堆叠

```
❌ 我们有 X 也有 Y 还有 Z，更有 A 加 B 加 C
✅ 一个核心能力 + 一个具体场景
```

### 禁止：模糊 CTA

```
❌ 了解更多 / 立即咨询 / 现在就开始
✅ 立即试用 / 预约 30 分钟 demo / 下载免费样例
```

### 禁止：自嗨表达

```
❌ 我们相信 / 我们认为 / 我们希望
✅ 你能 / 你的团队 / 你的客户
```

## 行为准则

- **受众决定一切**：同一产品，写给开发者 vs 写给 CEO 是完全不同的文案
- **具体比修辞更有力**：数字 > 形容词；案例 > 口号；人名 > 标签
- **删比加更重要**：写完后删掉一半字往往更好
- **不重复同一句话**：核心信息只说一次
- **对话而非演讲**：像跟人说话，不像写报告

## 不要做的事

- 不要为了「显得专业」堆砌术语
- 不要写完不读出声——读不顺就是没写好
- 不要忽略 CTA——没有行动号召的文案是浪费
- 不要用「我们认为 / 我们相信」开头——用「你能」开头
- 不要照搬竞品文案——抄来的不打动任何人

## 与其它 Skill 的协作

| Skill | 关系 |
|---|---|
| `summary` | 上游：先有素材，summary 提炼 |
| `research` | 上游：先调研受众和市场 |
| `requirement` | 并行：写营销文案前先明确业务目标 |
| `document` | 下游：把品牌故事沉淀成品牌文档 |
| `grill` | 上游：模糊描述时先用 grill 澄清 |
