# Brainstorm

发散思维，**生成尽可能多的可能性**——不评估、不筛选、不批评。

与 `grill`（收敛追问）正好相反：`grill` 把模糊变清晰，`brainstorm` 把清晰变多样。

## 何时使用

- 用户说「想点不一样的」「给我几个方案」「试试别的角度」
- 需求明确但不知从何下手
- 团队陷入思维定式，需要突破
- 需要快速做决策——但决策前先看更多可能性
- 设计初期需要铺开思路

不要用于：

- 需求还没澄清（先用 `grill`）
- 单一明确的实现任务（用 `coding`）
- 已经收敛到具体方案的执行（用 `task` 拆解）

---

## 与 grill 的关系

| 维度 | grill（收敛） | brainstorm（发散） |
|---|---|---|
| 方向 | 收窄、澄清 | 拓宽、生成 |
| 目标 | 把模糊变清晰 | 把清晰变多样 |
| 数量 | 1 个清晰的答案 | 多个可能的方向 |
| 评估 | 追问到满意 | 不评估，让用户挑 |
| 触发 | 「我想要 X」 | 「想点不一样的」 |

**先 grill 后 brainstorm**：当用户模糊时，先 grill 澄清；再 brainstorm 展开。

---

## 流程

### 1. 锚定起点

明确要从哪里发散：

- 要 brainstorm 什么？（问题 / 方案 / 命名 / 流程 / 视觉 / 体验）
- 已知约束是什么？（绝对不能越过的边界）
- 受众是谁？（如果是面向用户的设计）

### 2. 选择模式

四种模式，按场景选：

| 模式 | 触发场景 | 思维特点 |
|---|---|---|
| **standard** | 默认 / 不指定 | 多角度横向展开 |
| **lateral** | 「跳出框架」「换个角度」 | 强制切换视角 |
| **analogical** | 「像 X 一样」「类比」 | 跨行业类比 |
| **extreme** | 「最激进」「最保守」 | 推到极端反推 |

**默认 standard**，用户指定时用其它。

### 3. 生成方案

每个模式的具体技巧：

#### standard（标准发散）

从 5-7 个不同维度展开：

- 用户视角（不同角色会怎么想）
- 时间维度（过去 / 现在 / 未来）
- 空间维度（不同场景）
- 技术维度（不同实现方式）
- 商业维度（不同商业模式）
- 情感维度（不同情绪基调）
- 反向维度（反过来做）

#### lateral（跳出定式）

强迫切换视角：

- **初学者视角**：如果完全不懂这行，会怎么做？
- **外行视角**：完全不懂技术的人怎么理解？
- **5 岁小孩视角**：最简单的解释是什么？
- **历史视角**：100 年前 / 后会怎么处理？
- **反向视角**：反过来做会怎样？
- **限制视角**：只能用一个字 / 100 元 / 5 分钟，怎么做？

#### analogical（类比）

从其它行业 / 领域借思路：

- 餐饮业怎么做的？
- 医疗行业呢？
- 游戏行业呢？
- 教育行业呢？
- 政府机关呢？
- 生物界呢？（蚂蚁 / 蜂群 / 免疫系统）

#### extreme（极端）

推到极端再反推：

- **最简版**：只能做一件事，做什么？
- **最全版**：如果资源无限，能加什么？
- **最便宜版**：成本降到 1%，会怎样？
- **最快版**：时间降到 1%，会怎样？
- **最丑版**：完全不在乎美观，会怎样？

### 4. 输出

```markdown
# Brainstorm: <主题>

## 起点
[要 brainstorm 什么]

## 模式
[standard / lateral / analogical / extreme]

## 方案列表

### 方案 1: [简短标题]
[一句话描述 + 关键思路]

### 方案 2: [简短标题]
...

### 方案 N: ...

## 备注
- 这些方案不评估、不排序
- 用户自行选择深入方向
```

---

## 行为准则

- **数量胜过质量**：列出 10 个平庸的方案比 3 个精致的方案好
- **不批评**：不在 brainstorm 阶段评估可行性——那是后续的事
- **不重复**：每个方案必须真的有区别
- **允许疯狂**：极端方案往往最有启发
- **不评价**：避免「这个方案不好」「这个不现实」之类的自我审查

## 不要做的事

- 不要在 brainstorm 时考虑可行性（那是后续）
- 不要列重复的方案（同一个思路换个名字不算）
- 不要只列「安全的」方案
- 不要因为「用户可能不喜欢」就自我审查
- 不要混进 brainstorm 自己的判断（用 grill 或 design 之后再评估）

## 与其它 Skill 的协作

| Skill | 关系 |
|---|---|
| `grill` | 互补：grill 收敛，brainstorm 发散 |
| `design` | 下游：从 brainstorm 结果中挑一个深入设计 |
| `task` | 下游：brainstorm 完后拆任务执行 |
| `requirement` | 上游：先有需求再 brainstorm |
| `design-interface` | 互补：brainstorm 出 UI 风格候选，design-interface 深化 |
