# Prompt Writing

把意图 → 可控的 LLM prompt，让模型输出符合预期。**不调用 LLM**，**不写代码**，**不写应用逻辑**。

## 何时使用

- 写 system prompt（角色设定、能力边界、输出规范）
- 写 few-shot examples（让模型学格式）
- 设计 agent prompt（带工具调用 / 多步推理）
- 优化现有 prompt（token 效率 / 输出一致性）
- 写 evaluation prompt（评估模型输出质量）
- 写图像生成 prompt（Midjourney / Stable Diffusion）
- 写 RAG query prompt（检索增强生成的查询改写）

不要用于：

- 写应用代码（用 `coding`）
- 调用 LLM（Runtime 的事）
- 设计 AI Agent 架构（用 `design`）
- 业务需求分析（用 `requirement`）
- 设计运行时上下文的选择、排序、压缩、记忆和 Token 预算（用 `context-engineering`）
- 建立评估集、Rubric、评估器、指标和回归门禁（用 `llm-evaluation`）；只写 evaluator prompt 仍使用本 Skill
- 创建或维护 AOS Skill（用 `skill-authoring`）

---

## 核心原则

- **任务定义先于 prompt**：把意图用一句话写清楚，再围绕它设计 prompt
- **具体胜过抽象**：不要「写得好」，要「输出不超过 200 字 + 包含 3 个例子 + 用第二人称」
- **结构胜过叙述**：用列表 / 表格 / Markdown 而不是大段文字
- **示例胜过规则**：给一个完整的 few-shot 比讲十条规则更有效
- **边界条件显式列出**：不要假设模型会「自己想到」

## 流程

### 1. 明确任务

在写 prompt 之前先回答：

- 模型要做什么？（动词 + 单一目标）
- 输入是什么？（格式、长度、结构）
- 期望输出是什么？（格式、长度、结构）
- 评估成功的标准是什么？
- 边界条件是什么？（不该做什么、什么时候拒绝）

### 2. 选结构

按任务类型选：

| 任务类型 | 推荐结构 |
|---|---|
| 简单任务 | 直接指令 + 输出格式 |
| 复杂任务 | 角色设定 + 任务描述 + 输出格式 + 边界条件 |
| Agent / 多步推理 | 角色 + 工具列表 + 任务规划 + 反思 |
| Few-shot | 1-3 个高质量示例 + 任务 |
| 评估 prompt | 评分标准 + 例子 |
| 图像生成 | 主体 + 风格 + 光线 + 构图 + 参数 |

### 3. 写第一稿

按选定的结构写出来。然后检查：

- 任务描述是否明确（动词 + 单一目标）
- 输入 / 输出格式是否清晰
- 边界条件是否列出
- 示例是否相关（不脱离任务）
- Token 是否冗余

### 4. 自查 Hard Rules

- [ ] 任务用动词描述（「请做 X」而不是「请尽量...」）
- [ ] 边界条件显式（「不要做 X」「如果 Y 则拒绝」）
- [ ] 输出格式明确（结构 / 长度 / 语言）
- [ ] 没有歧义词（「清楚」「好」「简单」「自然」）
- [ ] 没有自相矛盾的指令
- [ ] Token 合理（不必要的「请」和「您」可去掉）

### 5. 输出格式

```markdown
# Prompt: <任务名>

## 任务
[一句话：模型要做什么]

## 输入
[输入格式与示例]

## 期望输出
[输出格式、长度、结构]

## 边界条件
- 不做：...
- 拒绝：...

## Prompt 正文

\`\`\`
[完整的 prompt 文本]
\`\`\`

## Few-shot Examples（如适用）

### Example 1
**Input:** ...
**Output:** ...

### Example 2
**Input:** ...
**Output:** ...

## Token 估算
- Prompt: ~X tokens
- 预期输出: ~Y tokens
- 总计: ~Z tokens
```

## Hard Rules（绝对禁止）

### 禁止：歧义词

```
❌ 写得清楚一点 / 自然一些 / 好一点 / 简单一些
✅ 输出不超过 200 字 / 用第二人称 / 包含 3 个具体例子
```

### 禁止：模糊拒绝

```
❌ 不要输出不合适的内容
✅ 如果请求涉及暴力、色情、隐私，拒绝并回复「无法处理」
```

### 禁止：堆叠指令

```
❌ 你应该 X，你应该 Y，你还应该 Z，你还要 W
✅ 任务：X。约束：Y。例外：Z。
```

### 禁止：缺少输出格式

```
❌ 请写一段话介绍这个产品
✅ 用 3 段输出：第 1 段用户痛点（50 字），第 2 段解决方案（80 字），第 3 段行动号召（30 字）
```

### 禁止：示例与任务脱节

```
❌ 任务是把中文翻译成英文，示例是讲笑话
✅ 示例是中文→英文翻译的真实案例
```

### 禁止：冗余礼貌语

```
❌ 麻烦您帮我... / 非常感谢... / 如果您能...
✅ 任务：...
```

## 行为准则

- **任务单目标**：一个 prompt 只做一件事；多任务就拆成多个 prompt
- **示例真实**：用真实场景的输入输出，不是凭空捏造
- **边界显式**：模型不知道「不该做什么」，要明确告诉它
- **Token 预算**：能用结构化（表格、列表）就不用叙述
- **可测试**：prompt 写完后用 5-10 个真实例子跑一遍，看输出一致性

## 不要做的事

- 不要写「请尽量 X，如果可以就 X，不然就算了」
- 不要在 prompt 里写完整的业务逻辑（那是代码）
- 不要把多个任务塞进一个 prompt
- 不要写完不测试——prompt 必须经过真实例子验证
- 不要照搬其他人的 prompt——每个任务有自己的最佳表达
