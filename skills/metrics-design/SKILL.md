# Metrics Design

设计产品 / 业务的指标体系。**不**做数据分析本身（用 `summary` / `research`），**不**写 SQL（用 `database`）。

## 何时使用

- 新产品从 0 设计指标体系
- 现有指标混乱，需重新梳理
- 团队对「北极星指标」有争议
- 需要对齐 OKR / KPI

不要用于：

- 已有指标，做报表 / 趋势分析 → `summary` / `research`
- 写 SQL / 建数据表 → `database`
- 设计用户调研 → `user-research`（待加）
- A/B 测试假设 → `ab-testing`

## 流程

### 1. 锚定业务目标

先问 3 个问题：

- 产品的**核心价值**是什么？（一句话）
- 用户**成功使用**是什么样？（具体行为）
- **赚钱方式**是什么？（订阅 / 广告 / 交易 / ...）

### 2. 选一个北极星指标（North Star Metric）

北极星 = 一个能反映用户从产品中获得价值的**领先指标**。

| 产品类型 | 北极星候选 |
|----------|-----------|
| 协作工具 | 周活跃协作文档数 |
| 电商 | 周购买用户数 |
| 内容 | 周阅读时长 |
| SaaS | 周关键操作数 |
| 社交 | 日活 + 互动比 |

**规则：**

- 反映**用户价值**，不是公司收入
- 能被**一线团队**影响
- **领先**于营收（不是滞后指标）

### 3. 选指标框架

按产品阶段选：

| 阶段 | 推荐框架 |
|------|----------|
| 早期（找 PMF） | AARRR（海盗指标） |
| 增长期 | AARRR + 漏斗细分 |
| 成熟期 | HEART（用户满意度） |
| 商业化 | 北极星 + 收入指标 |

#### AARRR

```
Acquisition     获客      注册 / 访问
Activation     激活      完成关键动作
Retention      留存      次日 / 7 日 / 30 日
Revenue        收入      付费 / ARPU
Referral       传播      邀请数 / 病毒系数
```

#### HEART（Google）

```
Happiness       满意度    CSAT / NPS
Engagement      参与度    使用频率 / 时长
Adoption        采用      新功能使用率
Retention       留存      持续使用
Task success    任务完成  核心路径成功率
```

### 4. 拆解为可执行指标

每个 AARRR 类别拆为 3-5 个**具体可测**的指标：

```
Retention（留存）
├── 次日留存率（D1 Retention）
├── 7 日留存率（D7 Retention）
├── 30 日留存率（D30 Retention）
└── 月活用户数（MAU）

Activation（激活）
├── 注册转化率
├── 首次关键动作完成率
└── 激活时间（注册到首次动作）
```

### 5. 看板分层

按**决策层级**组织看板（避免一次性看 50 个指标）：

```
┌─────────────────────────────────┐
│ 1. 高管看板（北极星 + 营收）       │  ← 1-3 个指标
├─────────────────────────────────┤
│ 2. 业务看板（AARRR 全景）          │  ← 10-15 个指标
├─────────────────────────────────┤
│ 3. 运营看板（漏斗 + 队列）         │  ← 按团队分
├─────────────────────────────────┤
│ 4. 实验看板（A/B 测试结果）        │  ← 按实验分
└─────────────────────────────────┘
```

每层只服务一个角色的一种决策。

## Hard Rules

### 禁止：指标过多

```
❌ 一次性设计 50 个指标
✅ 每层 ≤ 5 个核心指标
```

### 禁止：虚荣指标

```
❌ 注册用户数（不活跃也是注册用户）
✅ 周活跃用户（WAU）
```

### 禁止：滞后指标当北极星

```
❌ 把「季度营收」当北极星（已经发生）
✅ 把「用户关键动作」当北极星（领先）
```

### 禁止：脱离决策

```
❌ 「我们想看 X 指标」（没解释为什么）
✅ 「为了让 PM 决定是否砍掉 Y 功能，需要看 X 指标」
```

## 行为准则

- **决策导向**：每个指标必须支持一个具体决策
- **可影响**：团队能影响这个指标
- **领先**：比营收早几步
- **可测量**：数据可获得

## 与其它 Skill 的协作

| Skill | 关系 |
|---|---|
| `summary` | 上下游：先定指标（这个 Skill），再用 summary 分析 |
| `ab-testing` | 上下游：指标确定后做实验验证 |
| `cohort-analysis` | 上下游：指标确定后做队列分析 |
| `database` | 并行：指标需要数据库埋点支撑 |
