# Cohort Analysis

按「同一时期开始某行为」的用户分组分析。**不**做通用数据分析，**不**写 SQL。

## 何时使用

- 想理解「不同时间来的用户留存差异」
- 测算 LTV / CAC 评估获客 ROI
- 评估产品改动对留存的影响（同期群对比）
- 想识别高价值用户群

不要用于：

- 即时行为分析（点击、转化）→ `summary`
- 想验证单个改动效果 → `ab-testing`
- 写 SQL 取数 → `database`

## 流程

### 1. 定义同期群

同期群 = **同一时期开始某行为**的用户群。

| 同期群 | 定义 |
|--------|------|
| 获客同期群 | 同一周注册的用户 |
| 激活同期群 | 同一周完成激活的用户 |
| 付费同期群 | 同一周完成首次付费的用户 |
| 功能采用同期群 | 同一周首次使用某功能的用户 |

**关键：同期群的「开始时间」必须明确、可重复。**

### 2. 画留存矩阵

经典留存矩阵（获客同期群）：

```
        D0    D1    D7    D14   D30   D60
W1     100%   45%   22%   15%   10%    8%
W2     100%   48%   25%   18%   12%    9%
W3     100%   50%   28%   20%   14%   10%
W4     100%   52%   30%   22%   16%   —
...
```

**怎么看：**

- 每行 = 一个同期群（按开始时间）
- 每列 = 距开始时间的天数
- 单元格 = 该同期群在该天数的留存率

**关键观察：**

- 同期群之间**对比**（看产品迭代效果）
- 同一列**横向对比**（看同时期来的用户后续差异）
- 同一行**纵向衰减**（留存曲线）

### 3. 解读常见模式

| 模式 | 含义 | 行动 |
|------|------|------|
| 平坦衰减 | 留存稳定 | 健康产品 |
| 陡降后平 | 早期流失，后期稳定 | 优化激活 |
| 持续下降 | 留存越来越差 | 检查产品质量 |
| 后段时间反转 | 长期用户更活跃 | 关注老用户价值 |

### 4. 计算 LTV / CAC

#### LTV（Life Time Value）

**简化公式：**

```
LTV = ARPU × 平均生命周期 / 月
```

或：

```
LTV = (月均收入 / 月均流失率) × 毛利率
```

#### CAC（Customer Acquisition Cost）

```
CAC = 获客总成本 / 获客用户数
```

#### LTV / CAC 健康区间

| 比值 | 状态 |
|------|------|
| < 1 | 严重亏损 |
| 1-3 | 收支接近 |
| 3-5 | 健康 |
| > 5 | 增长受限（投入不足） |

### 5. 同期群对比

**A/B 测试后做同期群对比**——看改动是否真正提升留存：

```
        改动前 D30 留存    改动后 D30 留存    差异
W1             10%              12%         +20%
W2             12%              14%         +17%
W3             14%              16%         +14%
```

如果**新同期群持续优于老同期群**——改动真正有效。

## 输出格式

```markdown
# Cohort Analysis: <主题>

## 同期群定义
- 开始行为：[注册 / 激活 / 付费]
- 时间窗口：[按周 / 按月]
- 涵盖时段：[X 至 Y]

## 留存矩阵

| | D0 | D7 | D30 | D60 |
|--|----|----|-----|-----|
| W1 | 100% | 22% | 10% | 8% |
| W2 | 100% | 25% | 12% | 9% |
| W3 | 100% | 28% | 14% | — |

## 关键观察
- W3 比 W1 留存高 4pp → 产品迭代效果显现
- 所有同期群在 D7 衰减最大 → 早期激活需优化

## LTV / CAC
- 平均 LTV：¥360
- 平均 CAC：¥120
- LTV/CAC = 3.0 → 健康

## 建议
- [行动 1]
- [行动 2]
```

## Hard Rules

### 禁止：混淆同期群

```
❌ 把「付费用户」和「注册用户」放在同一同期群
✅ 明确每个同期群的「开始事件」
```

### 禁止：忽略样本量

```
❌ 「W20 同期群留存比 W19 高 5%！」（可能是噪声）
✅ 「至少 N 个用户的同期群才有统计意义」
```

### 禁止：用错留存定义

```
❌ 「30 天后登录」算留存，但用户可能订阅后就再也不登录
✅ 根据产品定义「有意义的行为」（如浏览 / 互动 / 付费）
```

### 禁止：跨产品对比 LTV

```
❌ 「我们 LTV 是 $100，但 Netflix 是 $200」（不可比）
✅ 同行业 / 同阶段对比
```

## 行为准则

- **明确定义开始事件**
- **保证样本量足够**
- **同一产品内对比，不跨产品对比**
- **看趋势，不看单点**
- **LTV / CAC 一起看**
