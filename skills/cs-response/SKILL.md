# CS Response

标准化客服**回复话术**，覆盖咨询、投诉、技术问题等场景。**不**做工单分类（那是 `support-triage`），**不**生成 FAQ（那是 `faq-generation`），**不**处理严重投诉升级（那是 `customer-recovery`）。

## 何时使用

- 客服日常回复客户
- 设计回复模板
- 培训新客服
- 统一品牌话术

不要用于：

- 工单分类 → `support-triage`
- FAQ 知识库 → `faq-generation`
- 严重投诉挽回 → `customer-recovery`

## 流程

### 1. 识别工单类型

按 `support-triage` 分类结果判断类型：

| 类型 | 优先模板 |
|------|----------|
| 咨询 | 友好、专业、详细 |
| 技术问题 | 清晰、有步骤、可执行 |
| 投诉 | 道歉、承认、共情 |
| 退款 | 快速、不扯皮 |
| 功能请求 | 感谢、记录、跟进 |
| 一般问题 | 友好、简短 |

### 2. 选择回复结构

**通用结构：**

```
1. 称呼与感谢
2. 确认理解问题
3. 解答 / 行动
4. 后续步骤
5. 进一步协助邀请
```

### 3. 关键原则

- ✅ **先共情，再处理**（情绪化客户尤其重要）
- ✅ **具体不模糊**（「24 小时内」而非「尽快」）
- ✅ **简洁清晰**（避免长段落）
- ✅ **避免术语**（客户视角的语言）
- ✅ **给客户选择**（不强迫）

## 回复模板

### 咨询类

```
Hi [客户名]，

感谢您的提问！

[直接答案]

操作步骤：
1. [步骤 1]
2. [步骤 2]
3. [步骤 3]

如有疑问请随时回复。

[客服名]
```

### 技术问题

```
Hi [客户名]，

我理解您遇到的 [问题描述] 问题。

**问题原因：**
[简短解释]

**解决方案：**

请尝试以下步骤：

1. [步骤 1]
2. [步骤 2]
3. 如未解决，请提供 [所需信息]

如果以上方法未解决，请回复 [附信息]，我们进一步排查。

[客服名]
```

### 投诉 / 不满

```
Hi [客户名]，

非常抱歉给您带来这样的体验。[具体复述问题]

我完全理解您为什么感到 [情绪]。

我们立即处理：
- [行动 1]
- [行动 2]
- [补偿方案]

[客服名 / 主管名]

[后续跟进承诺]
```

### 退款

```
Hi [客户名]，

您的退款申请已收到。

退款详情：
- 金额：[金额]
- 退款方式：[原路退回 / 其他]
- 预计到账：[时间]

退款处理中，有任何问题请回复此邮件。

[客服名]
```

### 功能请求

```
Hi [客户名]，

感谢您的建议！我们已记录：

- 您的建议：[复述]
- 提交时间：[时间]
- 跟踪编号：[ID]

我们的 PM 会评估，建议被采纳会在 [渠道] 通知您。

再次感谢！

[客服名]
```

### 不在服务范围

```
Hi [客户名]，

感谢您的咨询。

很抱歉，[具体服务 / 功能] 不在我们当前的服务范围内。

您可以尝试：
- [替代方案 1]
- [替代方案 2]
- [相关链接]

如有其他问题，请随时联系我们。

[客服名]
```

## 语气与风格

### 友好但不卑微

```
✅ 「很高兴为您服务」
❌ 「非常抱歉打扰您」（过度卑微）
❌ 「求您消消气」（讨好）
```

### 专业但不冷漠

```
✅ 「感谢您的反馈，我们会认真处理」
❌ 「我们理解您的感受」（机械）
❌ 「这是公司的规定」（冷漠）
```

### 简洁但完整

```
✅ 短段落 + 列表 + 关键信息加粗
❌ 大段文字 / 关键信息淹没
```

## Hard Rules

### 禁止：使用内部术语

```
❌ 「请检查您的 ETL pipeline 状态」
✅ 「请检查您的数据是否已更新」
```

### 禁止：模糊承诺

```
❌ 「我们会尽快处理」
✅ 「我们将在 24 小时内联系您」
```

### 禁止：把问题推给别人

```
❌ 「这是研发的问题，我们也没办法」
✅ 「我帮您转给研发，24 小时内给您反馈」
```

### 禁止：复制粘贴感

```
❌ 任何工单都用同样开头
✅ 针对具体客户问题定制
```

### 禁止：隐瞒信息

```
❌ 「这个功能暂时不能用了」（不解释原因和恢复时间）
✅ 「我们正在紧急修复，预计 [时间] 恢复」
```

## 行为准则

- **先共情，再处理**
- **具体不模糊**
- **简洁但完整**
- **避免术语**
- **承担责任，不推诿**
- **给客户选择权**

## 与其它 Skill 的协作

| Skill | 关系 |
|---|---|
| `support-triage` | 上游：分类后选择模板 |
| `customer-recovery` | 下游：严重情况升级 |
| `faq-generation` | 并行：高频回复沉淀为 FAQ |
| `copywriting` | 互补：营销场景用 copywriting |
