# Meeting Notes

把会议记录（口述、聊天记录、自动转写）整理为可执行的会议纪要。

## 何时使用

- 刚开完一个会，需要快速产出纪要
- 拿到一段会议录音 / 转写文字，需要提炼
- 跨时区团队异步会议，需要书面同步
- 决策需要追溯到源头

不要用于：

- 一对一闲聊
- 纯技术分享（用 `document` 写技术文档）

## 流程

1. **识别会议类型**：
   - 决策会：要结论与理由
   - 同步会：要状态、阻塞、下一步
   - 评审会：要 issues 与负责人
   - 规划会：要 scope、优先级、时间表
   - 复盘会：要 root cause、行动项、改进措施
2. **抽取关键信息**：
   - **决策**：拍板了什么
   - **行动项**：谁、做什么、什么时候
   - **风险 / 阻塞**：什么挡在路上
   - **待澄清**：没聊清楚、需要后续追的问题
   - **讨论要点**（次要）：背景与上下文
3. **过滤噪音**：寒暄、重复、车轱辘话不写
4. **标注来源**：关键决策标「谁说的」便于追溯
5. **分配行动项**：每条都要 owner + due date；不模糊到「大家看看」
6. **纪要分发**：会议结束 24 小时内发到所有相关人

## 输出格式

```markdown
# 会议纪要：[会议主题]

**时间**：2026-07-20 14:00-15:30
**主持**：张三
**出席**：张三 / 李四 / 王五
**缺席**：赵六（请假，会后单独同步）
**类型**：决策会

## 议程
1. 新功能优先级
2. 性能预算调整
3. 下季度路线图

## 决策

### D-001：先做订单模块重构
- 背景：当前订单模块代码债务严重
- 决策：本季度优先做
- 理由：[技术负责人陈述]
- 影响：延后 XX 功能

### D-002：性能 P95 目标从 500ms 调到 300ms
- 决策：采用更严格的 SLO
- 触发条件：业务量预计 2 倍增长

## 行动项

| ID | 内容 | 负责人 | 截止 | 状态 |
|----|------|--------|------|------|
| A-001 | 写订单重构方案 | 张三 | 2026-07-25 | TODO |
| A-002 | 性能基线测量 | 李四 | 2026-07-22 | TODO |
| A-003 | 同步赵六缺席内容 | 王五 | 2026-07-21 | TODO |

## 风险与阻塞
- 订单重构需要 DBA 协助，目前 DBA 排期满（→ 待跟进资源协调）
- 性能基线工具尚未部署（→ 阻塞 A-002）

## 待澄清
- 退款流程是否纳入本次重构？（决策会未达成，需单独讨论）
- 第三方支付通道的 SLA 是多少？

## 讨论要点（可选）
- 订单模型：保留现状 vs 重新建模
- 性能优化方向：缓存 vs 重写关键路径
```

## 关键要素

| 要素 | 必要 | 说明 |
|------|------|------|
| 时间 / 地点 / 方式 | 是 | 便于追溯 |
| 出席与缺席 | 是 | 缺席者需要单独同步 |
| 议程 | 是 | 控制会议范围 |
| 决策 | 看类型 | 决策会必须有 |
| 行动项 | 是 | 每条必须有 owner + due |
| 风险与阻塞 | 看情况 | 同步会 / 规划会需要 |
| 待澄清 | 看情况 | 评审会常出现 |
| 讨论要点 | 可选 | 长会需要让缺席者快速 catch up |

## 行为准则

- **24 小时内发出**：再晚就遗忘
- **决策可追溯**：记录是谁拍板、什么理由
- **行动项可执行**：不要写「再讨论一下」「后续跟进」（必须具体）
- **缺席者同步**：标出需要单独沟通的人
- **不复述发言**：只记结论；不复述某人说了什么话

## 不要做的事

- 不要把聊天记录原文粘贴
- 不要让纪要写得像会议录音文稿
- 不要把所有发言都列出来
- 不要让行动项没有 owner 或截止日期
- 不要把「讨论中」当「决策」

## 与其它 Skill 的协作

- 输出涉及需求 → 用 `requirement` 跟踪
- 输出涉及设计 → 用 `design` 跟进
- 输出涉及任务 → 用 `task` 录入
- 输出涉及风险 → 用 `security` 或 `performance` 评估
