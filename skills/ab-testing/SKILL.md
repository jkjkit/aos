# A/B Testing

设计并解读 A/B 测试。**不**做数据分析本身，**不**写实验代码（用 `coding`），**不**部署（用 `devops`）。

## 何时使用

- 想验证「哪个方案更好」（按钮颜色 / 文案 / 流程）
- 产品决策前需要数据支持
- 多个方案争执不下

不要用于：

- 想理解用户行为 → `summary` / `cohort-analysis`
- 改动是不可逆的（破坏性变更）→ 先灰度再 A/B
- 流量极小（< 1000 DAU）→ 显著性不足，直接决策即可
- 比较 LLM、Prompt、RAG 或 Agent 的离线质量与回归门禁 → `llm-evaluation`

## 流程

### 1. 明确假设

**好假设（Hypothesis）格式：**

```
因为 [预期原因]，
当 [改动 X] 时，
[指标 Y] 会 [变化方向 + 幅度]，
因为 [机制说明]。
```

**示例：**

> 因为按钮颜色影响视觉权重，
> 当把 CTA 按钮从蓝色改为橙色时，
> 点击率会从 5% 提升到 6%（+20%），
> 因为橙色在白色背景上更突出。

### 2. 定义指标

每个实验需要：

| 指标类型 | 含义 | 例子 |
|----------|------|------|
| **OEC**（Overall Evaluation Criterion） | 主要决策指标 | 点击率 / 注册转化率 |
| **护栏指标** | 不能恶化的指标 | 留存率 / 加载时间 |
| **诊断指标** | 解释为什么变化的指标 | 页面停留时间 |

**注意：OEC 必须是单一指标**，否则实验结果不明确。

### 3. 估算样本量

公式（简化）：

```
样本量 = 16 × p × (1 - p) / δ²
```

| 参数 | 含义 |
|------|------|
| p | 基线转化率 |
| δ | 期望最小可检测效应（MDE） |

**经验值（95% 置信度、80% 统计功效）：**

| 基线 | 检测 +20% | 检测 +10% | 检测 +5% |
|------|----------|----------|----------|
| 5% | ~30k | ~120k | ~480k |
| 10% | ~15k | ~60k | ~240k |
| 20% | ~7k | ~30k | ~120k |

**流量不足怎么办：**

- 选更大的 MDE（找更显著的差异）
- 跑更长时间
- 用更敏感的指标
- 直接做决定，不做实验

### 4. 设计变体

```
对照组（A）：当前版本
实验组（B）：改动版本
```

**规则：**

- 一次只改一个变量
- 多变量用「多变量测试」而非「串行 A/B」
- 改动要够显著才有意义

### 5. 随机化与分流

- **随机**：每个用户独立被分到 A 或 B
- **稳定**：同一用户多次访问看到同一版本
- **同时**：A 和 B 同时跑，避免时间干扰
- **独立**：不要让 A 和 B 互相影响（如共享缓存）

### 6. 收集数据并分析

跑够样本量后分析：

- 95% 置信度下 p < 0.05 才算显著
- 关注**效应大小**（不只是显著）
- 检查护栏指标是否恶化
- 检查新奇效应（用户初次见到的新版本可能短期波动）

### 7. 决策

| 结果 | 动作 |
|------|------|
| 显著且效应正向 | 推全量 |
| 显著但效应很小 | 看 ROI，决定是否推全 |
| 不显著 | 维持现状 |
| 显著但护栏恶化 | 回滚 / 不推 |
| 短期显著长期反转 | 不推 / 重新设计 |

## 输出格式

```markdown
# A/B Test Plan: <名称>

## 假设
[好假设格式]

## 指标
- OEC：[主要指标]
- 护栏：[1-3 个]
- 诊断：[2-3 个]

## 样本量估算
- 基线：[X%]
- MDE：[+Y%]
- 样本量（每组）：[N]
- 预计运行时长：[天]

## 变体设计
- A（对照）：[当前版本]
- B（实验）：[改动版本]

## 分流规则
- 用户分流：随机 / 稳定哈希
- 流量比例：50/50
- 排除规则：[bot / 新用户 / ...]

## 显著性检验
- 置信度：95%
- 统计功效：80%
- 检验方法：t 检验 / z 检验 / 贝叶斯

## 决策矩阵
- [结论 + 动作]

## 风险与缓解
- [新奇效应 / 学习效应 / ...]
```

## Hard Rules

### 禁止：实验期间偷看

```
❌ 跑 1 天看一次，「似乎有效，提前终止」
✅ 跑完样本量再分析
```

### 禁止：测试多个变量不区分

```
❌ 同时改按钮颜色 + 文案 + 位置 → 不知道哪个起作用
✅ 一次只改一个变量
```

### 禁止：用错指标

```
❌ 用「平均订单金额」做指标（少数高额拉高均值）
✅ 用「中位数」或「总额」
```

### 禁止：忽视护栏

```
❌ 主指标涨了，护栏指标跌了但不管
✅ 任何护栏恶化都必须分析原因
```

### 禁止：样本量不足下结论

```
❌ 「500 人测出来涨 5%，推全量」
✅ 「500 人样本量不够，需要 N = 30k」
```

## 行为准则

- **先算样本量再开实验**
- **一次只改一个变量**
- **看效应大小，不只是显著性**
- **护栏恶化 = 不推**
- **结果不显著 = 维持现状，不强行解释**
