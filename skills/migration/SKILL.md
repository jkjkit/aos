# Migration

为系统级变更（框架升级、数据库迁移、API 大版本切换、单体拆微服务）设计端到端的迁移方案。

## 何时使用

- 框架大版本升级（React 17 → 18、Spring Boot 2 → 3）
- 数据库迁移（MySQL → PostgreSQL、单库 → 分库）
- API 重大破坏性变更
- 单体拆分为微服务
- 老系统重写或迁到新平台

不要用于：

- 数据库表结构的 DDL 变更（用 `database`）
- 单文件代码改动（用 `refactor`）

## 核心原则：渐进，不要一刀切

> 任何超过 1 周、影响生产用户的变更，几乎都必须用「并行运行 → 逐步切流 → 全量验证 → 关闭老路径」的节奏。

一刀切的代价：

- 出问题就是全站
- 无法小范围验证
- 回滚代价巨大
- 用户感知明显

## 流程

1. **明确动机与目标**：为什么要迁；不迁会怎样；预期收益
2. **盘点影响面**：
   - 受影响的服务 / 模块
   - 受影响的 API 端点
   - 受影响的数据量
   - 受影响的用户 / 客户端
3. **选择迁移策略**：
   - **Big Bang**：一刀切；只适合影响小、可停机的场景
   - **并行运行**：新旧同时存在，按比例切流
   - **绞杀者（Strangler Fig）**：新系统逐步「绞杀」老系统，路由层切流量
   - **双写迁移**：数据层新旧双写，逐步校验一致性，最后切读
4. **数据迁移方案**：
   - 全量 + 增量（CDC / binlog / 时间戳）
   - 数据校验脚本（行数 / checksum / 抽样对比）
   - 回滚方案
5. **切流计划**：
   - 阶段：1% → 10% → 50% → 100%
   - 每阶段观察指标与告警
   - 明确「回滚条件」与「回滚命令」
6. **验证清单**：
   - 功能验证（核心路径）
   - 数据一致性（行数 / 抽样 / 关键指标）
   - 性能对比（P50 / P95 / P99）
   - 异常路径
7. **时间窗口**：选择业务低峰；避开大促 / 周末 / 月初
8. **沟通计划**：内部（团队、客服、运维）；外部（用户告知）
9. **回滚预案**：每阶段都可回；保留老系统一段时间

## 输出格式

```markdown
# Migration Plan: [主题]

## 动机
[为什么；不迁的后果]

## 影响面
- 服务：A, B, C
- API：/v1/orders, /v1/users
- 数据：users 表（约 500 万行）
- 用户：所有 Web + iOS + Android

## 策略
**绞杀者模式**：
- 新服务部署为 A'，与 A 并行
- API Gateway 按 header / 路由分流
- 阶段切流比例：1% / 10% / 50% / 100%

## 数据迁移
- 全量：2026-08-01 02:00 离线导出
- 增量：binlog CDC 实时同步
- 校验：行数 + 关键字段 checksum + 1% 抽样对比
- 切换：1 周稳定后切读，再切写

## 切流计划
| 阶段 | 比例 | 时间 | 验收 |
|------|------|------|------|
| 灰度 | 1% | D+1 | 错误率 < 0.1% |
| 小流量 | 10% | D+3 | P99 < 500ms |
| 大流量 | 50% | D+7 | 无新增客诉 |
| 全量 | 100% | D+14 | 7 天稳定 |

## 回滚
- 切流阶段：网关层路由回退
- 数据阶段：暂停 CDC + 切回老库
- 回滚决策人：[Tech Lead]
- 回滚时间窗：5 分钟内

## 沟通
- 内部：D-7 通知；D-1 提醒
- 外部：用户无感（接口兼容）；若有破坏性变更，D-30 发预告

## 风险
| 风险 | 缓解 |
|------|------|
| 数据不一致 | 双写 + 校验脚本 |
| 性能回退 | 灰度对比 + P99 监控 |
| 老客户端不兼容 | API 双版本并行 |
```

## 行为准则

- **可回滚优先**：写不出回滚方案就不要开始
- **小步切流**：1% 不丢人，100% 才危险
- **数据先于流量**：先把数据跑稳，再切流量
- **保持接口稳定**：迁移期双版本并行，避免客户端连锁升级
- **记录每个决策**：迁移结束写 ADR / 复盘文档

## 不要做的事

- 不要在周五下午切全量
- 不要把迁移和功能开发混在同一次发布
- 不要假设老系统能 24 小时待命兜底
- 不要跳过数据校验
- 不要让「迁移」变成无截止日的「半完成状态」
