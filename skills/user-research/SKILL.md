# User Research

理解**真实用户**的方法论——访谈、问卷、可用性测试、画像。**不**做数据分析（用 `data-analysis`），**不**写调研报告里的产品方案（用 `requirement` / `design`）。

## 何时使用

- 进入新领域 / 新用户群，需要理解
- 设计功能前想理解用户痛点
- 验证某个假设是否符合实际
- 流失用户调研

不要用于：

- 写需求规格 → `requirement`
- 画产品方案 → `design`
- 数据分析 → `data-analysis`
- 竞品分析 → `competitive-analysis`

## 主要方法

| 方法 | 适合什么 | 样本量 | 时长 |
|------|----------|--------|------|
| **用户访谈** | 深层动机 / 故事 | 5-15 | 30-60 分钟 |
| **问卷调查** | 量化偏好 / 行为 | 100+ | 自填 |
| **可用性测试** | 任务完成率 / 痛点 | 5-10 | 30-60 分钟 |
| **日记研究** | 长期行为 | 10-30 | 1-4 周 |
| **焦点小组** | 群体共识 | 6-12 | 1-2 小时 |

## 流程（以用户访谈为例）

### 1. 明确目标

- 这次访谈**回答什么问题**？
- 决策依据是什么（做完访谈要决定什么）？
- 受访者**筛选标准**是什么？

### 2. 写访谈提纲

**5 类问题：**

```
[热身]
- 自我介绍，介绍访谈目的（不引导）
- 你的日常工作 / 生活是什么样的？

[背景]
- 你在 [场景] 通常做什么？
- 多久一次？

[具体行为]
- 上次做 [任务] 是什么时候？
- 当时是怎么做的？（一步一步）
- 用了什么工具 / 找人帮忙？

[痛点]
- 哪个环节最让你头疼？
- 如果有魔法，最想改变什么？
- 试过什么办法解决？

[展望]
- 理想状态下，10 完美体验是什么样？
- 愿意为这个付多少钱 / 花多少时间？
```

### 3. 关键技巧

#### 多问「为什么」

```
- 你为什么用 X？
- 为什么不用 Y？
- 为什么这个对你重要？
```

#### 让用户讲故事，不要给答案

```
❌ 「你觉得 X 重要吗？」（引导）
✅ 「上次用 X 是什么时候？发生了什么？」（让 ta 讲）

❌ 「你会想要 X 功能吗？」（说「会」不代表真用）
✅ 「你上次想用 X 是什么时候？找到解决方案了吗？」（看真实需求）
```

#### 注意「说」与「做」的区别

```
- 人们说的 ≠ 实际做的
- 用 5 个「为什么」挖真实动机
- 关键节点用「show me」让 ta 演示
```

### 4. 现场记录

- **至少 2 人**：1 个访谈 + 1 个记录
- **录音 / 转写**：避免漏掉关键句
- **现场笔记**：关键词 + 表情 + 语气
- **不要**：边访谈边写大量笔记（影响观察）

### 5. 整理与编码

**Affinity Mapping（亲和图）：**

```
所有笔记
  ↓ 按主题分组
  ↓ 同一组 → 同一个洞察
```

**Persona（用户画像）：**

```markdown
# Persona: [角色名]

## 基本信息
- 年龄 / 职业：
- 技术水平：
- 设备：

## 目标
- 主要目标：
- 次要目标：

## 痛点
- 痛点 1：
- 痛点 2：

## 行为
- 典型场景：
- 工具偏好：

## 引述
- 「我每天花 2 小时做 X」
```

### 6. Jobs to be Done（JTBD）

**核心：** 用户不是在「买产品」，是在「雇产品完成任务」。

```
When [情境]
I want to [动机]
So I can [结果]

示例：
- When 我周末想做饭
- I want to 快速找到合适的菜谱
- So I can 在 30 分钟内做完
```

### 7. 报告输出

```markdown
# 用户研究报告: <主题>

## 研究目标
- 主要问题：
- 决策依据：

## 方法
- 受访者：[人数 / 筛选标准]
- 时间 / 方式：

## 关键发现

### 发现 1: [洞察标题]
- 证据：[引述 / 行为]
- 含义：[对产品的启示]

### 发现 2: ...

### Persona
- [画像 1]

### 痛点优先级
| 痛点 | 频次 | 强度 |
|------|------|------|
| ... | ... | ... |

## 建议
- [产品 / 设计 / 战略方向]

## 局限
- 样本量：
- 选择偏差：

```

## Hard Rules

### 禁止：诱导性问题

```
❌ 「你觉得 X 功能好不好？」（会得到「好」）
✅ 「你上次用 X 是什么时候？」（看真实使用）
```

### 禁止：5 人就下结论

```
❌ 「我访谈了 5 个人，他们都说 X」
✅ 「我访谈了 5 个人，这是初步观察，需要更大样本验证」
```

### 禁止：用访谈代替数据分析

```
❌ 「用户说他们想要 X，所以做 X」
✅ 「用户说想要 X，但实际行为数据 Y 显示...」
```

### 禁止：报告里夹带产品方案

```
❌ 「我们应该做 X 功能」
✅ 「用户痛点是 X，需要进一步评估产品方案」
```

## 行为准则

- **少问「你想要什么」，多问「你做了什么」**
- **观察 > 询问**：让用户演示而不是描述
- **小样本是洞察，不是结论**
- **记录原话**：避免转述失真
- **承认偏差**：清楚标注研究局限

## 与其它 Skill 的协作

| Skill | 关系 |
|---|---|
| `requirement` | 下游：研究 → 需求 |
| `design` | 下游：研究 → 设计 |
| `brainstorm` | 并行：研究后 brainstorming |
| `summary` | 上下游：报告可被提炼 |
