# Docs

## 目标

把需求和技术设计转化为可执行、可验证、可验收的阶段任务，并通过项目文档保持目标、实现和交付状态一致。

统一承担文档维护、阶段规划、测试与验收管理，避免拆成重复维护上下文的独立技能。文档应让读者快速找到理解、使用、开发和接手项目所需的信息。

## 适用场景

- 建立或整理项目文档结构
- 编写需求、技术设计和阶段任务
- 拆分阶段、安排依赖并定义验收标准
- 设计和执行必要的测试验证，记录阶段验收状态
- 更新使用说明、启动方式和常用命令
- 记录项目约定和关键决策
- 阶段结束、上下文切换或项目交接
- 检查文档与实现之间的差异

## 文档职责

优先沿用项目已有结构和命名。新项目可以采用根目录 `README.md` 与 `docs/` 下的项目文档，按实际需要逐步建立。

- `README.md`：项目简介、快速使用、常用命令、技术框架和核心逻辑图示，作为项目的阅读入口。
- `AGENTS.md`：项目目标、目录结构、开发约定、设计规范、换行符要求和注意事项。放在工具实际支持的加载位置；放在 `docs/` 时确认入口规则或配置能够引用它。
- `PRD.md`：用户、场景、目标、范围、业务规则和产品验收要求，说明需要解决什么问题。
- `TDD.md`：架构、模块边界、数据与接口、关键流程、技术取舍和验证方式，说明如何实现当前需求。
- `TASK.md`：阶段目标、范围、任务、依赖、验收标准、测试与验证方式，以及执行结果和状态。将 PRD 的产品要求和 TDD 的技术设计落实为当前阶段的交付计划。
- `MEMORY.md`：影响后续工作的关键决策、约束及必要理由，保持精简并清理失效内容。
- `HANDOFF.md`：项目全貌、当前阶段、近三期任务摘要、未解决问题和下一步，让接手者能够继续工作。

每类信息明确一个主要维护位置，其他文档通过链接引用。项目记忆存放项目决策，全局记忆只保留跨项目可复用的信息。

## 工作方式

### 了解现状

先阅读相关文档、项目约定和实际实现，确认本次要服务的读者、目的和范围。检查已有入口、链接、命令和状态，避免重复创建同类文档。

### 确定内容依据

根据用户确认的需求、代码、配置和验证结果写作。区分已实现行为、计划方案和待确认事项，不把设想写成现状。

文档之间或文档与代码存在冲突时，查明原因。需求偏差不能只通过修改文档掩盖；需要决定产品行为时，明确列为待决事项。

### 规划阶段任务

根据已确认的需求和设计拆分阶段，每个阶段应有清晰目标、范围和可独立检查的交付结果。按依赖和风险安排顺序，优先验证影响后续方向的关键假设。

在 `TASK.md` 中维护当前阶段的任务和验收标准。任务粒度以能够实施和验证为准，不把每个编辑动作拆成任务，也不提前细化尚未确定的远期需求。

验收标准描述可观察的结果，明确在什么条件下、执行什么操作、应得到什么行为。技术检查通过、功能验证通过和用户验收通过分别记录。

### 设计测试与验证

围绕阶段验收标准选择验证方式，可采用已有测试、构建、类型检查、接口检查、浏览器检查或人工操作。优先复用项目现有工具，不为简单变更引入测试框架。

根据影响和风险覆盖正常路径、关键边界、失败处理及相关旧功能。自动化测试应验证实际行为和重要契约，避免仅重复实现逻辑。简单、低影响的变更采用适度检查即可。

将必要的前置条件、测试数据、操作或命令和预期结果记录在 `TASK.md`。复用已有测试文件和命令，通过链接引用，避免复制成另一套测试说明。

### 执行验证与验收

在授权范围内执行阶段所需的检查，记录实际结果和失败证据。需要补充测试实现时结合 `coding`，发现故障时结合 `debug`，修复后重新验证受影响范围。

遵循项目的启动和验收约定。由用户启动项目或完成最终验收时，提供可直接操作的步骤和预期结果，将状态标为待用户验收，不自行认定通过。

验证受环境、依赖或权限阻碍时，记录阻碍及已完成的替代检查。测试通过不等于所有需求都已验收，未执行的检查不得标为通过。

### 组织和表达

先写读者需要采取的行动和理解的核心内容，再补充必要背景。使用清晰标题、简短段落和具体描述，避免空泛口号和重复规则。

命令说明执行目录、必要前提和预期结果。路径和链接应可定位；示例使用占位值，不写入密钥或个人敏感信息。

流程、依赖或模块关系适合用图时，优先使用易维护的 Mermaid。结构应帮助理解，不为凑章节保留空模板。

### 同步与精简

需求或实现发生变化时，更新直接受影响的文档，包括使用入口、接口、配置、任务状态和验收方式。保留必要的决策理由，不复制完整代码或重复维护同一份说明。

阶段完成后，记录关键决策并更新交接内容。`MEMORY.md` 只保留仍影响后续工作的信息；`HANDOFF.md` 聚焦当前阶段和近三期任务，更早且无当前价值的细节移出摘要。

任务完成状态必须有实现或验证依据。尚未验证、被阻塞或需要用户验收的事项应准确标注。

### 检查可用性

核对路径、链接、命令、示例、版本和状态是否与项目一致。检查读者能否找到启动、验证和下一步所需信息。

只执行已获授权且适合当前环境的验证。未执行的命令不声称已经通过，无法确认的内容明确标注。

## 交付标准

简要说明文档变化、当前阶段、任务进展、测试结果和验收状态，以及下一步或阻碍。修改保持在本次任务范围内，不自动迁移全局配置或提交 Git。
