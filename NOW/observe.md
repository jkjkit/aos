# Observe

## 目标

在分析、设计或实现之前，准确了解当前对象的状态、结构、入口、依赖和已有行为，为后续判断提供完整上下文。

观察阶段记录事实和证据，区分已经确认的内容、尚未读取的内容和无法确定的内容。

## 适用场景

- 接手陌生项目或新模块
- 开始编码、设计、审查或排查问题前
- 了解目录、配置、依赖、入口和运行方式
- 检查现有界面、交互流程和视觉系统
- 了解 Git 状态、近期变更和用户已有修改
- 对比文件、环境、服务或外部资料的当前状态

观察可以采用两种模式：

- 快速概览，用最少的读取建立项目或模块的整体地图
- 定向观察，围绕具体功能、问题或文件追踪详细上下文

## 工作方式

### 确定观察范围

先明确要了解的对象、观察目标和当前任务。按照目标选择相关文件、目录、页面、配置、命令、日志或外部资料。

避免无目的地扫描整个项目。优先从入口文件、项目说明、配置和用户提到的对象开始，再沿着调用关系或页面关系扩展。

### 建立现状地图

记录与任务相关的：

- 项目或模块的目录结构
- 功能入口、路由、命令和启动方式
- 关键文件、组件、类、函数和数据流
- 使用的框架、依赖、配置和环境要求
- 页面层级、主要操作、反馈状态和视觉模式
- 当前分支、工作区状态、近期提交和已有修改

根据对象选择需要记录的内容，不强行填写与任务无关的信息。

快速概览优先记录项目用途、技术栈、目录结构、启动入口、核心模块和当前状态。定向观察再沿着调用关系、页面关系或数据流深入。

### 查找关联上下文

阅读定义和调用方，确认一个功能从哪里进入、如何处理数据、最终产生什么结果。查看相关测试、文档、错误处理和配置，避免只根据单个文件推断整体行为。

观察已有界面时，检查不同页面、组件状态、屏幕尺寸和用户流程，记录重复模式与明显差异。

### 保留证据

记录文件路径、行号、命令结果、页面位置、截图或其他可以复核的证据。引用内容保持必要范围，避免复制与任务无关的大量材料。

对动态状态标明观察时间和环境。无法访问、无法复现或尚未确认的内容应明确记录。

### 保护当前状态

观察默认不修改文件、配置、依赖、Git 状态或运行环境。识别用户已有修改并保留它们。

需要运行命令、启动服务或打开页面时，优先使用不会改变项目状态的方式。可能产生文件、缓存、数据库或远程影响的操作应先确认范围。

## 输出方式

观察结果按以下顺序组织：

1. 当前对象和观察范围
2. 已确认的事实
3. 相关文件、入口和依赖
4. 当前行为或状态
5. 未确认内容和观察限制
6. 需要交给后续分析或实现阶段的问题

只输出与任务有关的观察结果。将事实、推断和待确认问题分开表达，不在观察阶段把未经验证的推断写成结论。

观察结果可以指出异常现象和待确认问题，但不比较方案、不评估成本收益，也不替用户做技术决策。

如果观察过程中发现明显异常，描述异常现象、证据和复现条件。问题原因、优先级和修复方案交给 `analyze`、`review` 或 `coding` Skill 处理。
