## 项目偏好

基于PRD.md和TDD.md文档实现，逻辑必须清晰，必要时需拆分阶段任务，设定验收标准，项目由用户启动，用户来验收结果

建立README.md、AGENTS.md、MEMORY.md和HANDOFF.md文档，区分好各自的职责

readme包含项目简介、快速使用、常用命令、技术框架、逻辑图示

agents包含明确的项目目标、大致的目录结构、项目偏好（如视觉设计规范、统一的的换行符）、项目注意事项

memory自动记录关键决策，记录方式言简意赅，必要时需更新删减，避免体积过大

handoff读完了解项目全貌和近3期处理的任务以及接下来要做的事情，不要把所有信息都放进来，聚焦当前阶段

代码注释要写的言简意赅且正式，说清楚这块代码的用途，这样设定的特殊原因，写的代码人也要易读才行

一个阶段完成后提醒提交git，提交前先review修复验证后再同步更新文档后再本地提交

项目参考目录结构（PRD和TDD文档会随着项目推进调整内容）

```
<project>/
├── .gitignore		# 忽略项（.env* / .next / dist / temp / node_modules 等）
├── docs/			# AGENTS.md、HANDOFF.md、MEMORY.md、PRD.md、TDD.md、TASK.md
├── temp/			# 临时文件、备份文件（可随时清理，不入版本库）
├── README.md		# 项目简介、快速使用、常用命令、技术框架、逻辑图示
├── start.bat		# 快速启动与停止脚本，只启一个后台窗口
└──	stop.bat		# 快速启动与停止脚本
```
