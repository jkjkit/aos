# Security Checklist

应用安全检查清单，用于代码审查和上线前检查。


---


## 认证和授权


### 密码安全


- [ ] 密码使用强哈希算法（bcrypt, scrypt, Argon2）

- [ ] 密码加盐（salt）且盐值唯一
- [ ] 密码强度要求（最少 8 位，包含大小写字母和数字）
- [ ] 不在日志中记录密码
- [ ] 密码错误次数限制（防止暴力破解）

### Token 管理


- [ ] 使用安全的 Token 生成算法

- [ ] Token 有合理的过期时间
- [ ] 实现 Token 刷新机制
- [ ] Token 可以被撤销
- [ ] 不在 URL 中传递敏感 Token

### 会话管理


- [ ] 会话 ID 随机且不可预测

- [ ] 登出后销毁会话
- [ ] 会话超时设置合理
- [ ] 防止会话固定攻击
- [ ] Cookie 设置 HttpOnly 和 Secure 标志

---


## 输入验证


### 数据验证


- [ ] 验证所有用户输入

- [ ] 白名单验证（而非黑名单）
- [ ] 验证数据类型、长度、格式
- [ ] 拒绝异常或恶意输入
- [ ] 在服务器端验证（不依赖客户端验证）

### SQL 注入防护


- [ ] 使用参数化查询

- [ ] 避免动态 SQL 拼接
- [ ] ORM 正确使用
- [ ] 输入转义处理
- [ ] 使用最小权限的数据库账号

### XSS 防护


- [ ] 输出编码（HTML, JavaScript, CSS, URL）

- [ ] 使用 Content-Security-Policy 头部
- [ ] 避免使用 innerHTML 直接插入用户输入
- [ ] 使用安全的模板引擎
- [ ] 设置 X-XSS-Protection 头部

### CSRF 防护


- [ ] 使用 CSRF Token

- [ ] 验证 Referer 头部
- [ ] 使用 SameSite Cookie 属性
- [ ] 敏感操作需要二次确认
- [ ] GET 请求不修改数据

## HTTP 安全头


### 必需的安全头


- [ ] Strict-Transport-Security (HSTS)

- [ ] X-Content-Type-Options: nosniff
- [ ] X-Frame-Options: DENY 或 SAMEORIGIN
- [ ] Content-Security-Policy
- [ ] X-XSS-Protection: 1; mode=block

### 推荐的安全头


- [ ] Referrer-Policy

- [ ] Permissions-Policy
- [ ] Cache-Control (敏感页面)

**示例配置：**


```javascript

app.use((req, res, next) => {
  res.setHeader('Strict-Transport-Security', 'max-age=31536000; includeSubDomains');
  res.setHeader('X-Content-Type-Options', 'nosniff');
  res.setHeader('X-Frame-Options', 'DENY');
  res.setHeader('X-XSS-Protection', '1; mode=block');
  res.setHeader('Content-Security-Policy', "default-src 'self'");
  next();
});
```

## 应急响应


### 发现漏洞时


1. **立即评估** - 影响范围、严重程度

2. **隔离问题** - 临时禁用相关功能
3. **快速修复** - 开发和测试修复方案
4. **部署上线** - 优先级最高
5. **通知用户** - 如果数据泄露
6. **事后分析** - 根因分析，防止复发
