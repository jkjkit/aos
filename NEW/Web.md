# Web — 联网检索与信源可信度分级规范

## 1. 目标与边界（Goal & Non-Goals）

- **核心目标（Goal）**：以**彻底达成目标**为最高导向，根据任务性质自动匹配**「模式 A：信息收集」**或**「模式 B：查找解决方案」**，通过深度正文核验完成检索，并对所有外部结论强制标注**信源出处**与**高/中/低三档可信度**。
- **非目标（Non-Goals）**：
  - 本地代码库已明确存在的内部事实，直接通过本地文件读取确认。
  - 未经用户明确授权，不在外部网站执行具有副作用的写操作（如提交表单、修改线上配置、发送消息等）。

## 2. 通用底座准则（Shared Rules）

### 2.1 工具协同与深度实证
- **目标导向与充分检索**：优先使用宿主环境的原生搜索/网页抓取能力进行多角度检索；在证据链完整或找到可行方案前不轻易中止，持续变换中英文术语、精确版本号或特征码深挖。
- **通用浏览器升级（`ego-lite` / `ego-browser`）**：当常规抓取无法获取完整正文、目标页面依赖前端动态渲染、需复用用户登录态或需网页交互时，向用户申请授权并调用 **`ego-lite`（`ego-browser`）** 执行（同一项目复用同一 `task / page`）。
- **正文实证约束**：搜索摘要（Snippet）仅作线索，关键事实、配置参数与代码方案必须进入目标页面读取完整上下文核实，禁止仅凭标题或残缺摘要下结论。

### 2.2 信源可信度三档标准（强制标注）
- **`[可信度：高]`**：官方文档、标准规范（RFC / W3C / MDN）、官方源码仓库（GitHub 源码、Release Notes、维护者确认的 Issue/PR）、官方公告与权威论文。
- **`[可信度：中]`**：主流技术社区（StackOverflow 高赞采纳回答、知名技术团队工程博客）附带完整可复现环境与版本说明的实测文章、多家独立信源交叉印证的报道。
- **`[可信度：低]`**：无一手出处的二手聚合/转载站、缺乏版本号与上下文的零散代码片段、对应大版本已发生破坏性更新的过时教程、未获交叉验证的单一孤证。

## 3. 双模式执行分流（Dual-Mode Workflows）

检索启动前，先判定当前任务属于哪一类模式，按对应策略执行：

### 模式 A：信息收集与事实调研（Info Gathering）
> **适用场景**：了解某个新领域/新工具、收集事实数据、梳理版本更新日志、对比开源库客观特性。
> **核心策略**：**重广度、重多源交叉、去主观偏见**。

1. **多视角发散检索**：从官方定义、核心架构、最新演进、社区真实评价四个切入点构造查询词。
2. **去伪存真与时间线对齐**：过滤营销软文与二手洗稿，优先提取一手数据、发布日期与适用版本；当不同信源数据冲突时，并列展示差异并按 `高可信度 > 低可信度`、`新近 > 历史` 给出采信判断。
3. **交付重点**：输出结构化的事实全景图、客观对比维度与原始出处链接，不掺杂未经实证的主观臆断。

### 模式 B：查找解决方案与排障（Solution Finding）
> **适用场景**：解决具体报错（Bug/Exception）、突破技术卡点、寻找特定业务场景的工程实现方案。
> **核心策略**：**重精准匹配、重根因机制、重前置条件与副作用核验**。

1. **特征码精确锚定**：
   - 先从本地提取精确环境基线（运行系统、框架/库精确版本、核心报错原文去路径噪音后的特征串）。
   - 构造高信噪比查询词（如 `"<报错核心串>" <库名> <主版本号>`，定向检索 GitHub Issues / Discussions / StackOverflow / 官方 Troubleshooting）。
2. **根因与适配性核验（严禁盲目搬运）**：
   - 找到候选方案后，必须核实 3 件事：**① 它解决的根因与本地问题是否真的一致？② 方案对应的版本与本地版本是否兼容？③ 是否引入副作用（如关闭安全校验、降级性能、破坏其他模块）？**
   - 优先采纳**治本方案（官方修复版本/标准配置）**；若仅有临时绕过方案（Workaround），必须显式注明其局限性。
3. **交付重点**：直奔主题输出 `问题根因 -> 首选可行方案（含适配条件） -> 备选/绕过方案 -> 验证方法`。

## 4. 输出格式规范（Output Schema）

根据所选模式，按对应模板交付（每项关键结论均须包含 `[可信度：高/中/低]` 标注）：

### 模板 A：信息收集报告（模式 A 交付）
1. **核心事实摘要**：提炼关键结论，行内标注 `（来源：<站点名>，[可信度：高/中/低]，时间/版本：<标识>）`。
2. **结构化信息矩阵**：
   | 维度 / 要点 | 客观事实内容 | 信源与链接 | 可信度 | 时效与备注 |
   | :--- | :--- | :--- | :---: | :--- |
3. **分歧与待考证项**：说明多源不一致之处或仅有低可信度孤证的信息。

### 模板 B：解决方案报告（模式 B 交付）
1. **根因定位**：一句话说明外部检索确认的触发机制 `（来源：<GitHub Issue/官方文档>，[可信度：高/中/低]）`。
2. **推荐解决方案**：
   - **首选方案（治本）**：具体操作步骤/代码调整 + **适用版本前提** + **潜在副作用说明**。
   - **备选方案（Workaround，按需）**：当首选方案受限于版本升级成本时的低成本绕过做法及风险。
3. **本地验证步骤**：验证该方案是否真正解决问题的最小检查动作。
