# UIUX — 极简直觉界面与视觉工程规范

## 1. 目标与边界（Goal & Non-Goals）

- **核心目标（Goal）**：构建直觉化、零解释成本、视觉高度统一且状态切换绝对稳定的用户界面。
- **非目标（Non-Goals）**：
  - 不做脱离功能效率的纯装饰性视觉堆砌。
  - 纯后端逻辑与非视图层重构不适用本规范（移交 `Coding`）；业务功能砍留取舍不在本规范内讨论（移交 `Analyze`）。

## 2. 判定准则与负向约束（Rules & Constraints）

### 2.1 可用性最高准则（三句重做定律）
- **一看就会**：界面元素的布局、图标与状态反馈必须符合直觉自明性。**若某个功能或交互需要超过 3 句话的使用说明才能让用户理解，则判定为设计失败，必须直接重做交互结构**（禁止通过堆砌长篇文字提示来弥补烂交互）。

### 2.2 全局视觉一致性规范（Design Tokens）
同一项目内必须复用统一的视觉基准，禁止跨组件随意发明内联魔法值：
- **色彩语义化**：严格限制主色、中性色与状态色数量；状态变化（常规 / 悬停 / 激活 / 禁用 / 警告 / 危险确认）优先通过**色彩与明暗对比度**清晰区分，无需额外文字弹窗干扰。
- **空间与排版**：间距统一遵循基准栅格（如 `4px / 8px` 倍数）；单页面字号层级控制在 **3~4 阶**以内（主标题、小标题/正文、辅助说明/标签），行高与字重保持全局一致。
- **圆角、边框与控件**：卡片、输入框、标签（Tag）与按钮（Button）的圆角半径（Border Radius）、边框粗细（`1px`）及内边距（Padding）在全局保持同一套尺寸梯度。

### 2.3 零布局抖动硬性约束（Zero Layout Shift）
任何交互触发、状态切换、数据加载或滚动条显隐，**窗口与周边元素严禁发生哪怕 `1px` 的位置跳动或尺寸抖动**：
- **滚动条防抖**：滚动容器强制预留滚动条槽位（使用 `scrollbar-gutter: stable` 或固定 `overflow-y` 策略），严禁因内容撑高出现滚动条导致页面横向挤压抖动。
- **状态切换防抖**：
  - 按钮、标签在不同状态（如：默认 $\rightarrow$ 加载中 $\rightarrow$ 已完成，或单击待删除态）切换时，必须锁定最小宽高（`min-width` / `height`）或采用等宽布局。
  - 选中/聚焦态若需高亮边框，必须预先设置 `border: 1px solid transparent` 或使用不占布局空间的 `box-shadow / outline`，严禁在 hover/active 时从 `0px` 突变为 `1px/2px` 边框。
- **异步内容防抖**：图片、抽屉预览或异步列表加载前，必须按已知宽高比（`aspect-ratio`）或固定高度渲染占位容器，防止加载完成后页面跳动。

### 2.4 微交互与文案铁律
- **两段式轻量化删除**：所有删除操作禁止弹出打断心流的模态确认框（Modal/Alert），统一采用**「单击短暂变色（进入高危待确认态，超时自动恢复） $\rightarrow$ 再次单击执行删除」**的原位交互模式。
- **同行精炼提示**：提示信息（Tooltip / 辅助说明 / 状态提示）必须**极致精炼、与标题同行排列且禁止折行**（`white-space: nowrap`）；无实际信息增量的废话提示（如在“名称”输入框下提示“请输入名称”）一律不写。

## 3. 执行流程与门禁（Workflow & Gates）

### Step 1：存量规范提取
1. 动手编写或修改界面前，先读取项目现有的全局样式文件（如 `globals.css`、`tailwind.config.*`、主题变量文件）及相邻核心组件，提取已有的颜色变量、圆角、字号与间距规范。

### Step 2：结构与防抖设计
1. 规划组件 DOM 结构与状态机（默认态、加载态、空状态、错误态、二次确认删除态）。
2. 逐项落实防抖措施（锁定尺寸槽位、滚动条稳定化、同行提示布局）。

### Step 3：交付自检门禁（Gate）
- **控制门禁（Gate）**：在交付代码或设计方案前，强制完成以下 4 项自检（任一项不达标必须修正后再交付）：
  1. **直觉核验**：不看任何说明文档，能否在 2 秒内看懂每个按钮的作用及当前状态？
  2. **防抖核验**：切换任意状态、触发二次单击删除、或内容溢出出现滚动条时，布局是否零位移？
  3. **文案核验**：是否存在换行的提示语？是否存在无实际价值的废话提示？
  4. **规范核验**：颜色、字号、圆角、间距是否与项目全局基准完全对齐？

## 4. 输出格式规范（Output Schema）

界面设计、审查或实现交付时，按以下结构汇报：

### 1. 交互与视觉设计要点
- **状态映射**：说明各交互状态（含单击变色二次删除、加载/激活态）的色彩与视觉反馈机制。
- **防抖与布局保障**：说明针对滚动条、动态状态切换及比例预览所采取的具体尺寸锁定方案。

### 2. 样式与组件实现（或审查修正清单）
- 提供符合全局 Design Tokens 的代码实现，或按 `问题位置 -> 违反条款 -> 修正方案` 列出 UI 审查清单。

### 3. 视觉验收标准
- 列出供用户在浏览器中直观验证的 2~3 个交互检查点（如：连续点击删除按钮观察变色与防抖表现、缩放内容观察滚动条零抖动等）。
